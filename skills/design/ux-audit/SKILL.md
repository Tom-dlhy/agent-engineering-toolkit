# ux-audit

## Walkthrough
Define primary personas and top tasks. Follow actual happy, empty, error, loading, keyboard and mobile paths. Note where users must guess what to do, where system status is invisible and where language is ambiguous.

## Findings
For each issue, document screen/path, user goal, observation, likely impact, severity and simplest feasible improvement. Separate observed friction from hypotheses requiring user testing. Prioritize blockers and accessibility before cosmetic changes.

## Validate
Check labels, focus order, contrast, target sizes, feedback, form errors, navigation continuity, content clarity and responsive layouts. Use browser inspection or usability evidence when available; don't claim real users were tested if they weren't.

## Output
A prioritized action list tied to expected user outcomes, not a generic list of UX principles.
